## 5. Defects Found & Fixed During Testing

1. **Audit Event Rollback on Cross-Project Span Violation (`server/app.js`):**
   - *Defect:* In `POST /api/projects/:projectId/records`, `logAuditEvent` for `CROSS_PROJECT_EVIDENCE_VIOLATION` was initially invoked inside `withTransaction(db, ...)` immediately before throwing `422 CROSS_PROJECT_EVIDENCE_VIOLATION`, causing SQLite's transaction rollback to undo the `ACCESS_DENIED` audit log entry.
   - *Fix:* Moved the span provenance and cross-project validation loop before `withTransaction(db, ...)` so `ACCESS_DENIED` audit events are durably committed before the `422` error is thrown. Verified in `tests/security_audit_stage08.test.js` Subtest 9.
2. **Body Parser Helper Reference in Stage 09 Routes (`server/app.js`):**
   - *Defect:* Stage 09 routes initially called `parseJsonBody(req)` instead of `readJsonBody(req)`.
   - *Fix:* Updated all Stage 09 routes and `/handovers/:id/publish` to call `readJsonBody(req)`. Verified in `tests/camera_step_up_stage09.test.js` (6/6 passing) and `tests/backend.test.js` (5/5 passing).
3. **Simulated Model Timeout & Upstream Extractor Failure Handling (`server/services/aiReconstructor.js`, `server/app.js`):**
   - *Enhancement for Stage 10 Reliability Testing:* Added explicit handling for model extraction timeouts (`504 MODEL_EXTRACTION_TIMEOUT`) and upstream extractor failures (`502 UPSTREAM_EXTRACTOR_FAILURE`), logging `RECONSTRUCTION_FAILED` to `audit_events` and ensuring zero partial records are written. Verified in `tests/e2e_reliability_stage10.test.js` Subtest 3.

## 6. Explicit Testing Limitations

- **VM DOM Harness vs. Multi-Engine Pixel Rendering:** Frontend views, event listeners, tab switching, filters, and API-backed DOM updates are tested in Node's `vm` DOM execution harness (`tests/frontend.test.js`) and static HTML/CSS inspection (`tests/e2e_reliability_stage10.test.js`). Visual pixel layout across physical Chromium/Firefox/WebKit viewports and hardware screen readers was not executed in a GUI browser during automated CLI runs.
- **Physical Camera Hardware:** As noted in Section 4, Stage 09 camera error/fallback/cancellation/MFA states are verified deterministically, while physical webcam frame rendering requires a user-operated browser with camera hardware.
- **Deterministic Local Extraction Engine:** Reconstruction runs deterministically against local source spans (`baton-local-deterministic / heuristic-span-reconstructor-v2`) so tests are 100% reproducible offline without external LLM API flakiness.
